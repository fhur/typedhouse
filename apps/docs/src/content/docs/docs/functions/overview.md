Functions build typed expressions inside query callbacks. Scalar methods transform or compare values; aggregate functions summarize groups of rows. They describe database work rather than executing JavaScript against fetched rows.

Each function below has its own page, with a complete TypeScript example and the **final SQL and parameters generated by the compiler**. The names are TypedHouse's public API names; emitted ClickHouse names can differ—for example, `element` emits `tupleElement`.

## Expression helpers

[Expression helpers](/docs/functions/custom-functions/) shows how to share business rules across queries: flag inventory for replenishment, calculate gross margin, and compose a contactability predicate. Each example includes its generated SQL.

The generated `functions.ts` also exposes known-function `fn` and `agg` calls; `.as(col.X)` declares their result descriptor without emitting a CAST. This is separate from custom function declarations, which were intentionally removed from scope along with custom aggregates and method extensions. Ordinary TypeScript expression helpers remain supported. Trusted scalar row SQL snippets require `.as(col.X)` for their runtime result descriptor. Interpolated values are parameters, not identifiers; authors are responsible for scalar, dependency-complete SQL and expression-position holes. No SQL lexer or sanitizer checks template text. Aggregate snippets and raw-query APIs remain unsupported.

This section covers the supported typed catalog. Individual pages explain the accepted descriptors and behavior.

`asc` and `desc` construct ordering specifications rather than scalar SQL calls; see [orderBy / thenBy](/docs/query-builder/ordering/). For subquery expressions, see [in / notIn](/docs/query-builder/set-subqueries/) and [scalar](/docs/query-builder/scalar-subqueries/).
